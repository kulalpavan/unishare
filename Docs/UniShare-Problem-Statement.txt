UniShare - Problem Statement and Solution
==========================================

PROBLEM STATEMENT
-----------------
Sharing folders, text, and files with other people usually requires accounts,
third-party cloud drives, or complicated permission setups, and the recipient
often has to sign in or install something before they can get the content.
There is a need for a simple website where a user can upload what they want to
share and instantly get a single share link that anyone can open and download
from directly.

WHAT THE WEBSITE SHOULD DO
--------------------------
1. Upload and share:
   - Folders
   - Text (notes / plain text content)
   - Files (single or multiple)
2. Generate a share link for every upload.
3. Allow the share link to be sent to anyone.
4. Recipients must be able to open the link and download the shared content
   directly, without creating an account.
5. Optional password protection:
   - The uploader can set a password on a share.
   - The recipient must enter the correct password before viewing or
     downloading the content.
6. Password-protected and unprotected shares should both be supported from the
   same interface.

PROPOSED SOLUTION
-----------------
Build a web application ("UniShare") with the following flow:

Pick files/folder/text -> Generate link -> Share -> Verify password (optional)
-> Download live, peer-to-peer

Frontend:
- A clean page where the user selects files, a folder, or types text.
- Options to set a password and (optionally) an expiry time for the share.
- After creating the link, show it with a copy button, a "don't close this
  tab" warning, and live download status (receiver connected, per-file
  progress, and confirmation once the receiver has downloaded everything).

Backend:
- Serves the frontend and runs a lightweight WebSocket signaling hub that
  introduces the sender's and receiver's browsers.
- No database and no file storage. File bytes and text stream directly
  between browsers over WebRTC data channels in 16 KB chunks.
- Returns a short, unique share URL such as:
    https://<domain>/s/<share-id>
- A share lives only while the sender's tab stays open. Closing the tab
  ends the share immediately.
- Rooms are ephemeral in-memory mappings holding the file listing, the
  password hash (never the plain password), and the expiry time.

Password protection:
- If a share has a password, the link opens a password prompt first.
- The password is verified by comparing SHA-256 hashes; the plaintext
  password never leaves the browser that typed it.
- Non-password shares open directly.

Recipient experience:
- Open link -> (enter password if required) -> preview text or see file/folder
  list -> download directly from the sender's browser, no sign-up needed.
- After the download completes, the sender is notified automatically.

Suggested tech stack (can be adjusted):
- Frontend: plain HTML/CSS/vanilla JS, no build step
- Backend: Node.js + Express (static files) + WebSocket signaling
- Real-time transfer: WebRTC data channels (+ STUN/TURN for NAT traversal)
- Passwords: SHA-256 hash comparison
- Cleanup: rooms expire on sender disconnect, on expiry, or after 24 hours

Key considerations:
- The sender must keep the tab open until the receiver finishes downloading.
- Large files need chunked handling with data-channel backpressure.
- Folders should preserve their internal structure and be delivered as ZIP
  (rebuilt in the receiver's browser).
- Share links should be hard to guess (random, high-entropy IDs).
- Symmetric NATs need a TURN server fallback for direct connections.
- Basic abuse protection (message size limits, one sender per room) for a
  public deployment.
